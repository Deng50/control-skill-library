# 原热管理 NMPC 到轻量策略

原对象上实跑了 16 个工况，每条 700 步、3,500 s。通过验证集选出的模仿策略有 3,539 个可训练参数。两个 PGAC 候选都完成了实际梯度更新，都在一项留出工况以更大的电池跟踪误差换来较低能耗。验证集未支持用它们替换模仿策略。[选择记录](../../runs/heat-policy/selected.json) · [逐工况结果与梯度记录](../../runs/heat-policy/report.json)

## 从库根运行

```powershell
$py = '..\control-agent-harness\.venv\Scripts\python.exe'
& $py -B cases\heat-policy\train_policy.py --collect
& $py -B cases\heat-policy\infer.py runs\heat-policy\imitation 253.15 263.15 1 293.15
& $py -B cases\heat-policy\live_expert.py --steps 3
```

第一条 Python 命令读取本地原始档案并复现训练、校验、选择和四路闭环。省略 `--collect` 可使用所附 [11,200 组状态转移](../../runs/heat-policy/expert.npz)。训练仍需同级素材目录中的源模型。第二条命令只依赖 PyTorch、推理脚本和包中的 `interface.json`、`inference.ts`；普通推理不加载项目代码或 CasADi。给定示例输出约为 205.10 rpm、3,968.38 W、0.98387。本次使用 CPU 单线程、PyTorch 2.7.1、NumPy 2.2.6、Python 3.10，随机种子 714。

第三条命令仅用于原 NMPC 的实时求解计时及最优轨迹成本复算。可运行 CasADi/IPOPT 的主机会记录每次求解、首拍冷启动、动作、原目标与重算目标。本机 Windows 应用控制阻止加载 CasADi 3.8.1 的扩展，另一个已有的 3.7.2 安装也未能加载。归档没有求解时延或逐次返回码，故实际专家时延与加速倍数目前没有测量值。[本机依赖探测](../../runs/heat-policy/live_expert.json)

## 1　采集与数据验收

读入同级 `备份2026.5.15/data_collection` 下带 Tb0、Tm0 的原专家 NPZ。相邻的 `data_collector.py` 调用 `create_default_controller(dt=5,horizon=50)`，用速度预见求出首个动作，送入 `SystemTestPlantAlign.step`，保存本拍执行前的状态、动作、车速及参考。专家、原对象、查表模型三份源码与 `素材/pgac` 文件逐字节一致；每个 NPZ 与速度文件都有 SHA‑256。原采集程序遇到求解失败会保持上次成功动作；16 条所选档案均无相邻三动作完全重复，但缺少逐拍求解状态，故不能由此认证每一步都求解成功。[档案来源、哈希与整轨划分](../../runs/heat-policy/data.json)

在查看动作和性能前固定 12 条训练、2 条验证、2 条测试轨迹。环境温度为 −20 或 −10 °C，电机初温高 10 K，SOC 从 1 开始。目标覆盖 10–25 °C，速度使用原文件的恒速工况及 UDDS、NEDC，每次以当前时刻与下一时刻插值，文件 km/h 转 m/s。训练集内距离上下限 2% 的样本数分别为泵 6,397/327，加热器 3,547/3,626，阀 927/6,961。系统长期贴边，按通道等权量程归一化后训练可防止加热器的瓦数主导损失。

每条档案从原初态重施原动作，三个记录状态在全部 11,184 组相邻行上的最大绝对差均为 0。末行的后继状态由同一原对象实际步进补齐。每条首行上一动作记为 [200,0,1]，以后一律使用此前真正施加的动作。原对象的四个热流记忆逐拍留存，仅供离线模型滚动初始化。IPOPT 档案存在浮点边界余差；在测试轨迹上加热器最大约 0.0000393 W。数据保留实际动作，约束计数采用每通道物理单位 0.0001 的容差。

## 2　相同 Actor 的模仿与复载

保留原核的 `ActorNet` 类、[Tb,Tm,SOC,Tb_ref] 观测次序和 sigmoid 后 0.005–0.995 的动作输出。三层隐层为 48、32、48，物理量程为 [200,1000] rpm、[0,4000] W 和 [0,1]。有效网络输出域约为 204–996 rpm、20–3,980 W、0.005–0.995，专家贴边时存在结构性误差。观测均值与标准差只用训练轨迹计算，验证 MSE 在第 450 次更新最低。专家可见未来车速及内部热流，学生只读取四个当前量，因此无法完全还原所有专家动作。测试教师状态上三个通道的 RMSE 为 214.27 rpm、912.51 W、0.26358。[实际推理包接口](../../runs/heat-policy/imitation/interface.json)

两个 PGAC 分支都在全新实例上严格加载这一热 Actor 的三层权重、输出层与训练缩放。第一次更新前在同一组 128 个样本的物理输出差均为 0。独立加载 TorchScript 后也与模仿策略逐点相同。导出含权重哈希、原对象身份、数据哈希、动作单位及输出顺序。[导出与训练实现](train_policy.py)

## 3　成本、延迟与 PGAC 梯度

每拍指标取执行 `u[k]` 后的 Tb[k+1] 与本拍参考。跟踪项为 (Tb[k+1]−r[k])²/16，功率项为 P²/1,600,000,000，老化项为 300,000,000·ΔC²。P=Ph+0.00002n²+0.0038n+0.2589。老化增量用执行前 SOC、Tb、泵和加热器功率及源专家的加减速转矩、驱动/回馈效率计算电流，再代入执行后的 Tb。闭环 J 是在原对象实测状态上逐拍累计该专家公式；50 步专家规划内部的预测最优值属于另一项量。电机上限 333.15 K 在原专家中是硬约束，学习策略按实测超限步数单独考核。功耗另换算 Wh。

成本复算直接提取原专家源文件中的转矩、电流、功率、容量衰减及三项加权表达式，以原查表的线性外推实现数值评价。Torch 梯度路径用相同公式，并对近零电流使用有理化表达式。128 个训练样本三项最大绝对差为 8.75×10⁻⁵、7.60×10⁻¹⁰、1.82×10⁻⁶。原 PGAC 核名义动力学沿用限幅加速度和线性泵功率。它与原对象、专家预测都有已知偏差；本实验在两条 PGAC 分支中使用相同的名义动力学和真实对象校准的热参数，另行对齐评价及求导目标中的专家电流与功率。抽查时线性式与专家功率差最高 4,315.8 W。

原对象初始四个热流记忆均为零。原对象首拍用当拍实际动作计算两路原始热流并初始化全部记忆，随后用前拍原始流更新有效热流，电池与电机的时间常数分别为 300 s 和 20 s。专家求解器的自身初始热流使用 [200,0,1]，每次求解前用上次动作及当前状态更新其记忆。二者首拍协议有差别。专家动作取自原采集结果；PGAC 在原对象的任意中段起滚时用真实配对转移记录的四个初始热流，随后只递推自己的热流与预测状态。故意重置中段记忆使相同样本的 J 变化 −0.39836。

原始热 Critic 的输入参数中有 perception，但原版实测三步调用数为 0，将感知参数整体加 3 后 J 同为 166.88754。其时间索引在循环内不前移，原版实测三次均输入同一速度对 [2.205,4.455] m/s。本例按动态工况逐步前移，前述三个正确速度对为 [2.205,4.455]、[4.455,6.705]、[6.705,8.3333]。固定时间索引使本例 12 步 J 变化 −0.26962。[原核和故障探针](../../runs/heat-policy/report.json)

感知模块使用原 `PerceptionNet`，接收三状态、三动作、环境温度和两拍车速，对真实后继状态减名义后继状态进行监督学习。只用训练轨迹拟合输入和残差缩放；冻结参数后保留对输入及动作的梯度。验证 RMSE 由 [0.0003684 K, 0.027017 K, 0.00003986 SOC] 降至 [0.0001119 K, 0.002761 K, 0.00000108 SOC]。同一组起点、同一 Actor 的名义/耦合 J 分别为 133.21214/133.24515，耦合支实际调用感知 12 次，Actor 梯度差 L2 为 0.0062024。

两个候选使用相同批次、相同初始权重及 Adam 步长 0.00012，每支更新 14 次，每批 64 个训练起点。为控制 CPU 成本，PGAC 预算为 12 步、60 s；专家预算为 50 步、250 s。两种模型分别测得首轮梯度范数 0.51965 与 0.51494，最大参数变化为 0.001687 与 0.001693。本例采用离线配对转移上的原生 Actor/感知网络和适配滚动，不包含长期在线探索或原训练器全程复现。

## 4　闭环决策

先按执行器、电机超限步数排序，再按两条原对象验证轨迹平均 J 排序。三种学习策略均无超限，模仿、名义、感知耦合的平均 J 为 9,901.49、9,905.58、9,905.57；测试前据此冻结模仿包。测试中每个策略从相同初态独立驱动原对象。档案专家重放已验证与历史真实专家闭环逐步一致，只用于本批已知工况的对照。

|---|---|---:|---:|---:|
| NEDC，−10 °C 环境，15 °C 目标 | 专家 | 3,762.12 | 5.011 | 1,703.55 |
| 同上 | 模仿 | 3,891.00 | 5.780 | 1,771.17 |
| 同上 | 名义 PGAC | 3,890.03 | 5.817 | 1,749.09 |

| 90 km/h，−20 °C 环境，25 °C 目标 | 专家 | 18,824.86 | 14.335 | 2,258.56 |
| 同上 | 模仿 | 19,118.29 | 14.546 | 2,284.12 |

所有留出策略均满足电机限值，在容差内执行器超限为 0。模仿的总 J 比专家高 3.43% 和 1.56%。CPU 逐拍计时覆盖 NumPy 状态构造张量、运行 TorchScript、转回物理动作数组；两条测试轨迹的模仿推理 p95 约 0.2 ms。该计时不含被控对象步进和进程加载。NEDC 上降低电耗伴随电池 MAE 变差，90 km/h 上两项均改善。两个测试工况不能确定增加车速预见、引入动作历史或扩大 PGAC 时域在其他环境的收益。

## 使用技能时遇到的问题

| 环节 | 本次实际遇到的问题 | 能复查的处理 |
|---|---|---|
| 采集与导入 | 通用入口的示范固定为弹簧二维状态和单个对称力，热档案有三维非对称动作、速度预见与四个对象记忆 | 检查三通道边界覆盖，验证原文件哈希、车速单位、原对象转移、上一执行动作和时间戳。交换泵/加热器、标签错一拍、改采样周期、丢热流均触发错误 |
| 模仿与交接 | 仅凭相同 `state_dict` 键或隐藏尺寸无法核实信号与输出端点 | 签入对象、语义、物理量程和缩放参数，验证复载与两支优化前相同 |
| PGAC | 只查感知参数或验证有限 J 无法发现未参与递推、冻结外生输入或泵功率式不同 | 实际探测感知调用次数、J、梯度、真实速度对和源成本表达式；比较验证集逐状态预测误差 |
| 选择与时延 | 测试集上某支降低 J 不足以改变已冻结的验证决策；档案的文件读取耗时不能代表专家求解 | 保存测试前选择与权重哈希，四路独立闭环，分别记录模型推理、原始求解状态和可获得的时间 |
